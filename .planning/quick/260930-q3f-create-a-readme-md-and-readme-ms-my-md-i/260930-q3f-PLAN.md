**Section 1 — Prerequisites: Node.js, npm, npx**
- npm and npx ship WITH Node.js — installing Node.js is enough.
- Windows: download LTS installer from https://nodejs.org or `winget install OpenJS.NodeJS.LTS`
- macOS: download LTS installer from https://nodejs.org or `brew install node`
- Verify: `node -v`, `npm -v`, `npx -v`

**Section 2 — OpenCode (https://opencode.ai)**
- macOS: `curl -fsSL https://opencode.ai/install | bash` (easiest), or `brew install anomalyco/tap/opencode` (recommended over plain `brew install opencode` — updated more frequently), or `npm install -g opencode-ai`
- Windows: upstream recommends WSL for best experience; native options: `choco install opencode`, `scoop install opencode`, or `npm install -g opencode-ai`
- First run: `opencode` in a project → use `/connect` → sign in at https://opencode.ai/auth (or another provider) and paste API key → `/init` in a project creates AGENTS.md.

**Section 3 — gsd-opencode (https://github.com/rokicool/gsd-opencode)**
- Easiest: `npx gsd-opencode` (or `npx gsd-opencode@latest`). Works on Mac, Windows, Linux.
- Or: `npm install gsd-opencode -g` then `gsd-opencode install`
- Non-interactive: `npx gsd-opencode --global` (installs to ~/.config/opencode/) or `npx gsd-opencode --local` (installs to .opencode/)
- Verify with `/gsd-help` in OpenCode. Restart OpenCode after install so slash commands load.
- Update: `npx gsd-opencode@latest` or `gsd-opencode update`. Uninstall: `gsd-opencode uninstall`.
- After install: `/gsd-set-profile` (simple/smart/genius) — restart OpenCode after changing.

**Section 4 — OpenChamber (https://github.com/openchamber/openchamber — web/desktop workspace for OpenCode)**
- Desktop app (macOS/Windows/Linux): download from https://github.com/openchamber/openchamber/releases/latest — bundles the matching OpenCode CLI, so no separate OpenCode install needed.
- CLI for Web/PWA: requires Node.js 22+. Install: `curl -fsSL https://raw.githubusercontent.com/openchamber/openchamber/main/scripts/install.sh | bash`
- Run: `openchamber --ui-password be-creative-here` (binds to localhost by default; only use `--lan` on trusted networks; ALWAYS protect with --ui-password — put this warning in bold in both languages).
- Common commands table: `openchamber status`, `openchamber connect-url --qr`, `openchamber tunnel start --provider cloudflare --mode quick --qr`, `openchamber startup enable`, `openchamber logs`, `openchamber stop`, `openchamber update`

**Section 5 — Tailscale (https://tailscale.com — private network/tailnet to reach your machine remotely)**
- Windows: installer from https://tailscale.com/download or `winget install Tailscale.Tailscale`; log in via system tray → browser
- macOS: App Store ("Tailscale") or `brew install --cask tailscale`; log in via menu bar → browser
- Admin console config (https://login.tailscale.com/admin) — 5 numbered items:
  1. MagicDNS — enable (Settings → DNS) so devices reach each other by name
  2. HTTPS certificates — enable (Settings → DNS → HTTPS Certificates) for `tailscale serve` HTTPS
  3. Access controls (ACLs) — default allow-all is fine for a personal tailnet; tighten later
  4. Key expiry — Settings → Keys, or per-device re-authentication period; disable expiry for your own always-on machine if desired
  5. Device approval — Settings → Device management, turn on approval for new devices (recommended)
- Typical use: install Tailscale on the PC running OpenChamber + on phone/laptop, then reach the OpenChamber web UI from anywhere via the tailnet.
- Command examples: `tailscale status`, `tailscale ip`, `tailscale serve --bg <port>` (exposes local service over HTTPS on the tailnet)

**Section 6 — Verify everything** — a short checklist table mapping each tool to its verify command (`node -v`, `opencode --version`, `/gsd-help`, `openchamber status`, `tailscale status`).

How It Works — the 6 steps, each with the slash command as a code block + 2-4 translated lines:
1. `/gsd-new-project` — one flow: Questions → Research (parallel agents) → Requirements (v1/v2/out of scope) → Roadmap (phases). Creates PROJECT.md, REQUIREMENTS.md, ROADMAP.md, STATE.md, .planning/research/. Already have code? Run `/gsd-map-codebase` first.
2. `/gsd-discuss-phase 1` — captures implementation preferences before planning; system identifies gray areas per phase type (visual → layout/density/interactions; APIs → response format/flags; content → structure/tone; org tasks → grouping/naming). Creates {phase}-CONTEXT.md.
3. `/gsd-plan-phase 1` — researches (guided by CONTEXT.md), creates 2-3 atomic task plans as XML, verifies plans against requirements in a loop. Creates {phase}-RESEARCH.md, {phase}-{N}-PLAN.md. Each plan is small enough to execute in a fresh context window.
4. `/gsd-execute-phase 1` — runs plans in dependency-ordered waves (independent plans parallel, dependent sequential); fresh context per plan; atomic commit per task; verifies against goals. Creates {phase_num}-{N}-SUMMARY.md, {phase_num}-VERIFICATION.md.
5. `/gsd-verify-work 1` — user acceptance testing: extracts testable deliverables, walks through them one by one, auto-diagnoses failures, creates fix plans. Creates {phase}-UAT.md.
6. Repeat discuss→plan→execute→verify per phase; then `/gsd-complete-milestone` (archives + tags release), `/gsd-new-milestone` for the next version.

Quick mode: `/gsd-quick` — ad-hoc tasks with the same planner+executor quality, skips research/checker/verifier, tracked in .planning/quick/ not phases. Use for bug fixes, small features, config changes, one-off tasks.

Why It Works — short subsection per pillar (translate prose, keep names in English): Context Engineering (PROJECT.md vision always loaded; research/ ecosystem knowledge; REQUIREMENTS.md scoped v1/v2; ROADMAP.md where going/what's done; STATE.md decisions/blockers/memory across sessions; PLAN.md atomic XML task + verification; SUMMARY.md what happened; todos/ captured ideas — size limits based on where OpenCode quality degrades); XML Prompt Formatting (every plan is structured XML: name/files/action/verify/done — precise instructions, no guessing, verification built in); Multi-Agent Orchestration (thin orchestrator spawns specialized agents: 4 parallel researchers; planner+checker loop; parallel executors with fresh 200k context; verifier+debuggers — main context stays at 30-40% because work happens in fresh subagent contexts); Atomic Git Commits (each task gets its own commit immediately — git bisect finds the exact failing task, each task independently revertable, clear history); Modular by Design (add phases, insert urgent work between phases, complete milestones, adjust plans without rebuilding).
